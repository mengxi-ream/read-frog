feat(subtitles): show translations right away at the start of a video and after a seek

AI subtitles now send every line of the next 30 seconds at once, instead of one batch at a time. A line about to show before its AI translation arrives gets a Microsoft machine translation in the meantime, unless you have switched Microsoft Translator off under API providers. A line already on screen keeps that translation until it ends, and the transcript shows the AI translation at once. A batch that fails is now sent again 10 seconds later, or as soon as another batch comes back, instead of leaving its lines untranslated. While the line on screen has failed and no batch has come back since, the error shows in place of the subtitles, and it goes away by itself once a batch comes back. When the error is one every later batch would get too, such as a wrong key (401), an empty balance (402, or an OpenAI account with no balance), no permission (403), a wrong model (404), or Built-in AI refusing, translation stops at the first failure: the machine translations are removed, and the error stays on screen in place of the subtitles until you come back to the tab or change the subtitles provider. A subtitle error from a provider with your own key now starts with that provider's name, such as "OpenAI: You exceeded your current quota…", so it does not read as Read Frog's own. For a wrong key or no permission (401, 403), a rate limit (429) or a server error (500, 502, 503), the error now says so in Read Frog's words, as it was meant to; other errors, and an empty balance, keep the provider's own message. A long error is now cut short at the player's edge, with the whole text on hover. An OpenAI account with no balance is no longer retried as a rate limit for several minutes. Looking up a word in a subtitle now uses only the original line as context.
